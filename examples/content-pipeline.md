# 内容流水线：选题 → 初稿 → 人审 → 发布

> 一个人做内容号时，让找料、起草、审稿、发帖分给不同 bot，只靠文件交接，人只在选项卡上点一次批准。

- **适合**：每天要发几条短帖、已经有 2 个以上专项 bot，想把「AI 写完直接发」变成有人把关、可复盘的流水线
- **验证日期**：2026-10-21
- **验证级别**：✅ 实测（投稿者在 Grok Bot 里连续多周每天真跑；待维护者复核。文中 bot 名、路径、帖子样例均已脱敏或虚构）
- **成本量级**：中（4 个 bot + 每条帖子一条一次性 routine + 每晚 1 条对账 routine）

## 场景

一个 bot 既找料又写稿又发帖，常见结果是：数字没出处、标题越写越夸张、同一件事一天发三遍、半夜发帖，出错了也说不清是哪一步。

拆成五段，**写稿和审稿分开，批准只认人**：

| 角色 | 只做 | 不做 |
|---|---|---|
| 找料 bot（X 简报 / GitHub 热门仓库） | 定时出简报，每条带来源链接，写进交接文件夹 | 写帖子 |
| 发推 bot | 从简报挑题，起草约 2 条，附 `sources.md`；批准后建定时发帖 | 自己判断「可以发了」 |
| 审稿 bot | 逐条审稿，写 `review.md`，附完整修改版 | 改原稿、发帖 |
| 人 | 看全文，在选项卡上选「批准 / 改时间 / 不发」 | — |
| 总管 bot（可选） | 每晚对账、出日报 | 替人批准 |

## 输入

- 共享交接文件夹，例如 `/workspace/shared/handoff/`（简报）和 `drafts_{{日期}}_{{批次}}/`（每批稿件一个文件夹）
- 每批文件夹里固定几样：`post_N.txt`（原稿）、`post_N_v2.txt`（修改版）、`sources.md`、`review.md`、`STATUS.txt`（批准记录，只追加）
- 一张总表 `board.csv`：`date,time,type,topic,status,url,source_url,views,likes,bookmarks,notes`，status 用 drafted / scheduled / posted / rejected / held
- 排期规则：同一账号两条帖子间隔 ≥30 分钟；本地时间 23:00 后不发（回复除外）
- 证据规则：每个数字带来源链接和核实日期；推测单列；查不到出处的数字不写
- 写作规则（写进发推 bot 的 skill）：非长文只挑重点、先说「它能干什么、怎么开始用」

## 步骤

1. **找料（定时）**：找料 bot 按固定时段出简报，存进交接文件夹，每条：一句结论 + 来源链接 + 发布时间
2. **起草**：发推 bot 只读简报，挑约 2 个题，写 `post_1.txt`、`post_2.txt` 和 `sources.md`（帖子里每个数字对应一行来源）；建议发帖时间写进文件夹
3. **审稿**：审稿 bot 逐项检查——事实是否和来源一致、有没有夸大、AI 腔、隐私泄露、和已发/已排的帖子撞题、长度、时区换算、「今天/昨天」按**发帖当天**是否还对。写 `review.md`（每条给结论：可发 / 小改 / 大改 / 不建议发），并附完整修改版 `post_N_v2.txt`
4. **人工闸门**：把修改版**全文**发给人，配一张选项卡（如「都按建议时间发 / 只发第 1 条 / 改到明天 / 先都别发」）。人选了才算批准，bot 之间的「我看没问题」不算
5. **记账**：批准结果追加进 `STATUS.txt`（时间 + 批准了哪个文件 + 几点发），`board.csv` 改为 scheduled
6. **定时发帖**：每条帖子建一条**一次性** routine。到点后：
   - 发前查账号最近若干条，确认没发过
   - 原样粘贴已批准的文件，粘贴后读回比对
   - 只点一次发布
   - 发后再查一次，确认只有一条、全文一致；结果写进发帖日志
7. **复查**：约 20 分钟后再查一次重复和浏览数，回填 `board.csv`，然后 routine 删掉自己；帖子链接发给人
8. **对账（每晚）**：陪跑监督 routine 核对：已批准的是否都发了、有没有重复、有没有漏建或残留的 routine，总管 bot 出日报

原则：**文件交接、批准只认人、发帖只发已批准文件的原文**。

## Prompt

发推 bot（起草）：

```text
你是 {{账号定位}} 的发推助理。只读 {{简报路径}}，挑 2 个最值得发的题。
每条写一份 post_N.txt：
- 先说它能干什么、怎么开始用，挑重点，不堆功能
- 每个数字都要在 sources.md 里有一行：数字 | 来源链接 | 核实日期
- 没有来源的数字不写；推测要写成推测
- 日期写具体日期（如 10/20），不要只写「今天」「昨天」
最后写一行建议发帖时间（本地时间，与已排帖子间隔 ≥30 分钟，不晚于 22:30）。
不要发帖，不要建 routine，等人批准。
```

审稿 bot：

```text
你是审稿助理。审 {{稿件文件夹}} 里的每条 post_N.txt，对照 sources.md 和 board.csv。
逐项检查并写进 review.md：
1. 事实：每个数字、引语是否与来源原文一致（贴出原文）
2. 夸大：有没有来源里没有的「永久」「最强」「省 N 倍」
3. AI 腔：套话、排比、空洞收尾
4. 隐私：账号名以外的私人信息、路径、地点
5. 撞题：和最近 7 天已发、已排的帖子是否同一件事或同一个模板
6. 长度：非长文超出要点的部分，建议删哪句
7. 时区和日期：按「计划发帖当天」重算「今天/昨天」，换算成本地时间
每条结论只能是：可发 / 小改 / 大改 / 不建议发。小改以上附完整修改版 post_N_v2.txt。
不改原稿，不发帖。
```

一次性发帖 routine：

```text
到点执行，只发 {{已批准文件路径}}，不改一个字。
1. 发前查账号最近 10 条，已有相同内容就停，报告给我
2. 粘贴文件全文，读回比对一致
3. 只点一次发布
4. 发后确认只有一条、全文一致，链接写进发帖日志和 board.csv
5. 约 20 分钟后再查一次重复和浏览数，回填后删除本 routine
任何一步失败：停下、不重试发布、报告给我。
```

## 产出

虚构示例：

```text
# drafts_{{日期}}_am/STATUS.txt
{{日期}} 09:42 人批准：post_1_v2 13:05；post_2_v2 15:40（本地时间，间隔 ≥30 分钟）

# 发帖日志
{{日期}} 13:05,posted,post_1_v2 准点发出；发前查重通过；发布键只按一次；发后核对全文无差异
{{日期}} 13:26,recheck,仍只有一条；浏览 {{浏览数}}
{{日期}} 13:26,routine deleted

# review.md（节选）
| 稿 | 结论 | 一句话 |
| post_1 | 小改 | 标题写「全网最快」，来源只说「比上一版快」，改回来源原话 |
| post_2 | 大改 | 第二段的下载量查不到出处，删掉；结尾套话删去 |
```

## 坑

- **错过发帖时间**：定时 routine 没按时跑，帖子没发。别补发到原时间附近撞车，按「间隔 ≥30 分钟」顺延到下一个空档，并在 STATUS.txt 记一笔
- **稿子太长被退回**：人嫌长、说不清能干什么。后来把「挑重点、先说怎么用」写进发推 bot 的 skill，审稿 bot 专门查长度并给删减建议
- **两条用了同一个模板**：同一批两条结构一模一样，读者一眼看出是批量生产。审稿时把「和同批、近几天的帖子是否同一模板」加进撞题检查，其中一条换写法
- **把「昨天」写成「今天」**：稿子前一天写、第二天早上发，正文里的「今天（某日）」到发帖时已经不对。审稿 bot 发现时离发帖只剩十几分钟，靠紧急暂停 routine 才拦住，人改成「昨天」后再发。对策：起草就写具体日期；审稿按发帖当天重算
- **bot 回复语言漂移**：发推 bot 的设定写着用中文，几轮对话后自己变成了英文回复。对策：语言要求写进 bot 记忆，日报里顺带检查
- 定时发帖最怕重复：发前、发后、复查各查一次，只点一次发布，失败不自动重试
- 一次性 routine 记得发完自删，不然每晚对账会看到一堆残留
